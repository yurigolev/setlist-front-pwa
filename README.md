# Setlist

PWA для репертуара музыкантов: вход через Яндекс, совместные сетлисты, песни, заметки, изображения аккордов и один MP3-плейбэк на песню. Сервер хранит данные и проверяет права; подтверждённая копия выбранного сетлиста доступна на устройстве офлайн.

Основная цель MVP: после первого запуска с сетью установленное приложение должно открываться, искать сохранённые песни и воспроизводить вложения в авиарежиме.

## Возможности

- создание и редактирование песен: название, исполнитель, свободные заметки;
- сетлисты: создание, выбор, переименование и удаление владельцем;
- участники owner/editor/viewer, одноразовые приглашения с отзывом;
- owner и editor изменяют и удаляют песни/вложения, viewer читает и скачивает;
- независимая копия песни со всеми вложениями в другой доступный для записи сетлист;
- изолированный кэш метаданных и файлов в IndexedDB по пользователю и сетлисту;
- изображения аккордов в PNG, JPEG и WebP;
- один MP3-плейбэк на песню и встроенное воспроизведение;
- поиск по названию, исполнителю и заметкам без сетевых запросов;
- сортировка по алфавиту или дате изменения, фильтр песен с плейбэками;
- теги с фильтрацией по любому выбранному тегу, необязательным цветом и палитрой / колор-пикером в настройках;
- устанавливаемая PWA с offline app shell.

## Технологии

- Vue 3, TypeScript и Vite;
- Vue Router и Pinia;
- IndexedDB через `idb`;
- Vite PWA / Workbox;
- Vitest.

Требуется Node.js 22.22.1 или новее (в Docker и CI используется Node.js 24).

## Форматирование и Git hooks

`npm install` автоматически подключает Husky через `prepare`. Перед каждым коммитом
`lint-staged` проверяет только staged-файлы: ESLint исправляет JS/TS/Vue, затем Prettier
форматирует код и поддерживаемые документы. При ошибке коммит прерывается; исправьте её
и повторите коммит. Исправления автоматически попадают в staged-файлы.

```sh
npm run lint          # Проверить код
npm run lint:fix      # Исправить доступные ESLint нарушения
npm run format       # Отформатировать проект
npm run format:check # Проверить форматирование без записи
```

Сборки, зависимости, lock-файл и локальные QA/agent-артефакты исключены из обработки.
Если зависимости установлены с `--ignore-scripts`, выполните `npm run prepare` вручную.

Используем рекомендованные правила ESLint, TypeScript и Vue; `eslint-config-prettier`
отключает конфликтующие правила форматирования. Prettier: 2 пробела, одинарные кавычки,
точки с запятой, trailing commas, строка до 100 символов и LF. EditorConfig и
`.gitattributes` задают одинаковые отступы и окончания строк в редакторах и Git.
CI проверяет весь проект командами `lint` и `format:check` перед тестами и сборкой.

## Проверка PWA на iPhone

Для офлайн-приёмки используйте production-сборку, а не `npm run dev`:

```sh
npm run build
npm run preview -- --host ::1 --port 4173 --strictPort
```

Чтобы открыть preview на iPhone из внешней сети, во втором терминале поднимите временный Cloudflare Tunnel:

```sh
cloudflared tunnel --url 'http://[::1]:4173' --no-autoupdate
```

Откройте выданный `https://*.trycloudflare.com` адрес в Safari, выберите «На экран Домой», дождитесь первого запуска с сетью, затем перезапустите приложение в авиарежиме. Подробнее о туннеле — в [TUNNEL.md](TUNNEL.md).

## Данные и ограничения MVP

Сервер хранит песни и вложения. Очистка данных Safari удаляет локальную офлайн-копию; после входа и обновления сетлиста приложение загружает её снова. Без сети доступен только последний выбранный сетлист последнего подтверждённого пользователя, без изменений. Выход удаляет личный кэш. При подключении приложение повторно проверяет сессию и доступные сетлисты, удаляет кэш отозванных или удалённых сетлистов.

Песня принадлежит ровно одному сетлисту. «Копировать в другой сетлист» создаёт отдельную песню и отдельные вложения: последующие изменения не связаны. Владелец управляет участниками, приглашениями и сетлистом; редактор управляет содержимым; viewer только читает. Последнего владельца нельзя удалить или понизить. Ссылка приглашения имеет вид `/invite#token=…`; для принятия требуется вход через Яндекс. Токен остаётся в браузере на время входа и удаляется после принятия.

Поддерживаются изображения `PNG`, `JPEG`, `WebP` и аудио `MP3`. Ограничения PWA и доступный объём проверяются на целевом iPhone; приложение запрашивает persistent storage, но браузер может отказать.

## Подключение к backend

Для полноценной локальной работы с Яндексом запускайте постоянный Docker-стек:

```sh
npm --prefix ../setlist-back run local:up
```

Открывайте **http://127.0.0.1:46544**: этот origin и callback зарегистрированы для локального Яндекс-входа. Стек собирает текущий frontend и API, запускает PostgreSQL/MinIO на отдельных постоянных volumes `setlist-yandex-pgdata` и `setlist-yandex-miniadata` и автоматически поднимается после перезапуска Docker. Старые Telegram volumes не переиспользуются. Настройка: [docs/YANDEX-AUTH-LOCAL.md](docs/YANDEX-AUTH-LOCAL.md). `localhost:5173` остаётся dev-сервером интерфейса; для текущего конфига Яндекса входите через `127.0.0.1:46544`, чтобы callback и cookies использовали один host.

Резервная копия базы и файлов:

```sh
npm --prefix ../setlist-back run local:backup -- /Users/1g/Backups/setlist-local-YYYY-MM-DD-HHMM
```

Для разработки интерфейса `.env.local` задаёт `VITE_API_BASE_URL` и `VITE_API_PROXY_TARGET` для Vite proxy `/v1`. Для туннеля и подключения iPhone по USB следуйте [TUNNEL.md](TUNNEL.md). Сервисный работник кэширует оболочку приложения, а подтверждённый снимок с файлами хранится в IndexedDB. Старые локальные тестовые песни не отправляются на сервер.

Для HMR с рабочим Яндекс-входом на том же адресе `http://127.0.0.1:46544` сначала поднимите стек командой выше, затем из каталога frontend выполните:

```sh
docker compose --project-directory ../setlist-back --env-file ../setlist-back/.env.yandex.compose.local -f ../setlist-back/docker-compose.yandex.yml stop pwa
VITE_API_BASE_URL='' VITE_API_PROXY_TARGET=http://127.0.0.1:46543 npm run dev -- --host 127.0.0.1 --port 46544 --strictPort
```

API, PostgreSQL и MinIO продолжают работать в Docker; Vite занимает только порт интерфейса. Для возврата к собранному Docker-интерфейсу остановите Vite через `Ctrl+C` и выполните `npm --prefix ../setlist-back run local:up`. Холодный офлайн-запуск проверяйте на production-сборке, поскольку HMR не кэширует всю оболочку.
