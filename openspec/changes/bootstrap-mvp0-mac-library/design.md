# Design

## Context

Репозиторий пуст; требуется заложить MVP 0 с нуля. Целевое поведение определено в `proposal.md` и трёх delta-specs: установленная PWA на iPhone должна надёжно открывать библиотеку и её файлы без сети. Это планирующая поставка: кода приложения в ней нет.

## Goals / Non-Goals

**Goals:**

- Создать одну PWA, которую можно установить из Safari на экран «Домой» iPhone без нативной подписи.
- Сохранить библиотеку и вложения в браузерном хранилище, наблюдать квоту и результат запроса persistent storage.
- Дать каждую пользовательскую ценность вертикальным коротким этапом с проверяемым результатом.

**Non-Goals:**

- Не проектировать протокол синхронизации, серверную БД или авторизацию.
- Не добавлять Capacitor, нативную SQLite или нативную файловую систему, пока PWA не провалит практическую офлайн-приёмку.
- Не вводить теги отдельной сущностью: на MVP 0 пользователь может писать хештеги в свободных заметках.
- Не реализовывать синхронизацию между Mac и iPhone: в испытательной поставке данные добавляются на целевом iPhone.

## Decisions

### Vue 3 PWA на TypeScript и Vite

Приложение будет создано как Vue 3 + TypeScript + Vite PWA, с Vue Router для экранов, Pinia для состояния, web app manifest и service worker. SSR, SEO и публичные страницы отсутствуют, поэтому Nuxt добавил бы сложность без пользы. Service worker кэширует app shell, чтобы после первого запуска пользователь мог открыть интерфейс с экрана «Домой» в авиарежиме. Альтернатива — нативный контейнер — отклонена, пока PWA не доказала недостаточность на реальной библиотеке.

### Свободная доменная модель и локальный порт хранилища

Модель `Song` содержит `id`, `title`, опциональные `artist` и `content`, массив `attachments`, `createdAt` и `updatedAt`. Вложения содержат собственный идентификатор, `songId`, тип `image` или `audio`, имя, MIME-тип и локальный ключ файла. UI обращается к интерфейсу репозитория песен и вложений, а не напрямую к IndexedDB. Альтернатива — хранить MP3 как BLOB в записи песни — отклонена: метаданные и содержимое файлов должны быть отделены уже сейчас.

### IndexedDB и Storage API для PWA

Метаданные песен и бинарные `Blob` вложений хранятся в IndexedDB в одном браузерном профиле. Это работает офлайн и поддерживает объёмные файлы лучше, чем `localStorage`. При первом использовании приложение запрашивает persistent storage и читает `navigator.storage.estimate()` для статуса использованного и доступного объёма. Отказ браузера или ошибка квоты не блокируют приложение, но отображаются без ложного обещания сохранности. Альтернатива — только `localStorage` — отклонена из-за малого лимита и неэффективности MP3; backend — вне scope MVP 0.

### Локальный поиск в MVP 0

Поиск реализуется по нормализованным строкам `title`, `artist` и `content` после загрузки локального списка в память. Для нескольких сотен песен это предсказуемо и достаточно быстро. SQLite FTS5 переносится в MVP 1, когда появится нативная локальная БД; преждевременное добавление FTS в Web не требуется.

### Вложения: выбор файла на iPhone, проверка до записи и object URL для показа

Основной способ добавления на iPhone — системный выбор файлов; drag-and-drop остаётся ускорителем на Mac. Принимаются PNG/JPEG/WebP и MP3 с проверкой MIME-типа и/или расширения. Файл записывается до отображения как сохранённый; для предпросмотра и аудио создаётся временный object URL, который освобождается при размонтировании экрана. Альтернатива — base64 в данных песни — отклонена из-за роста размера и памяти.

## Risks / Trade-offs

- [Браузер не выдаёт persistent storage или устройство испытывает дефицит места] → показывать результат persistent-запроса и квоту, перехватывать ошибку записи и не отображать не сохранённый файл; в следующей поставке рассмотреть экспорт библиотеки.
- [Пользователь очищает данные Safari или меняет origin] → использовать один стабильный HTTPS-origin, явно сообщать о локальной природе данных и не удалять файлы молча.
- [Service worker не закэшировал app shell] → проверять первый запуск с сетью и отдельный запуск установленной PWA в авиарежиме на iPhone.
- [Нет фоновой докачки] → не обещать фоновую синхронизацию; все добавления и проверка готовности выполняются при открытом приложении.
- [Время добавления превышает 30 секунд] → оценить workflow на пяти реальных песнях после каждого вертикального этапа и убрать лишние поля/подтверждения.
- [Крупные изображения замедляют экран песни] → на MVP 0 не преобразовывать файлы, но показывать по одному с ленивой загрузкой при необходимости; оптимизацию зафиксировать только после измерений.

## Migration Plan

1. MVP 0 публикуется на одном стабильном HTTPS-origin и устанавливается на целевой iPhone из Safari.
2. Перед любым изменением origin или переходом к нативному контейнеру добавить экспорт из IndexedDB или явный одноразовый импорт; не удалять локальные данные автоматически.
3. При ошибке развёртывания откатить статическую версию на том же origin; пользовательские данные остаются в браузерном хранилище.

## Open Questions

- Нужна ли пользователю поддержка нескольких MP3-плейбэков у одной песни или достаточно одного для первого теста UX? Спецификация допускает несколько, но UI можно начать с первого доступного.
