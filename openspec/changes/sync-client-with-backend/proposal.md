## Why

Библиотека PWA сейчас живёт только в IndexedDB одного устройства. После появления собственного backend клиент должен записывать песни и файлы на сервер, а локально хранить подтверждённую копию для просмотра без сети.

## What Changes

- Подключить PWA к уже реализованному публичному API одной библиотеки из backend change `add-offline-sync-backend` в репозитории `setlist-back`, используя опубликованный `openapi.yaml` как контракт.
- Направить создание, редактирование и удаление песен и вложений сначала на сервер; без сети оставить последнюю синхронизированную библиотеку доступной для чтения.
- После записи, при запуске с сетью и по команде пользователя получать полный снимок сервера и сохранять песни и файлы в IndexedDB.
- Сохранить одну кнопку «Сохранить» в форме, при этом отдельно передавать текст и бинарные файлы; показывать частичный успех и конфликты вместо ложного сообщения о полном сохранении.
- Не переносить тестовые данные со временного origin на постоянный адрес.

## Capabilities

### New Capabilities

- `server-backed-library-client`: серверная запись песни и вложений, локальная копия полного снимка, офлайн-чтение и понятные состояния синхронизации.

### Modified Capabilities

Нет: main specs пока не содержат опубликованных capability. Активный `bootstrap-mvp0-mac-library` описывает прежний локальный MVP; его спецификации нужно синхронизировать либо архивировать до публикации новой capability, чтобы не оставить противоположных требований к сохранению без сети.

## Impact

- Изменятся доменная модель, IndexedDB-схема, репозитории, store, форма песни и библиотека.
- Клиент зависит от OpenAPI-контракта backend change `add-offline-sync-backend`; потребуется сопоставить текущие `content`/`name` с серверными `notes`/`filename` и сделать исполнителя обязательным при серверной записи. Авторизация и очередь офлайн-правок остаются за пределами MVP.
- Текущая локальная тестовая библиотека на временном origin не импортируется в серверную БД.
