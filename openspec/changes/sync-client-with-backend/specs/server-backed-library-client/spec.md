## Purpose

Позволяет PWA работать с серверной библиотекой как источником данных и сохранять подтверждённый снимок с файлами для использования без сети.

## ADDED Requirements

### Requirement: Клиент соблюдает контракт опубликованного API

PWA SHALL использовать настраиваемый базовый URL backend и контракт `/v1` из OpenAPI. Создание SHALL передавать непустые `title` и `artist`, а клиентское `content` SHALL сопоставляться с серверным `notes`. Имя вложения SHALL читаться из `filename`; `fileKey` SHALL оставаться только локальным указателем Blob. Относительный `contentUrl` SHALL разрешаться относительно базового URL backend.

#### Scenario: Создание песни

- **WHEN** пользователь сохраняет новую песню с названием, исполнителем и текстом
- **THEN** PWA отправляет `POST /v1/songs` с `title`, `artist`, `notes` и стабильным `Idempotency-Key`

#### Scenario: Отображение файла

- **WHEN** снимок содержит вложение с `filename` и относительным `contentUrl`
- **THEN** PWA показывает имя файла и получает его содержимое по адресу backend; при общем production origin запрос проходит через frontend proxy к API

### Requirement: Запись песни сначала на сервер

PWA SHALL отправлять создание, текстовую правку через `PATCH /v1/songs/:id` и удаление через `DELETE /v1/songs/:id` на backend до изменения локальной копии. Правка и удаление SHALL передавать `If-Match` с текущей ревизией песни. Без доступа к backend PWA SHALL сообщать, что для записи нужна сеть, и SHALL не показывать несохранённую правку как сохранённую.

#### Scenario: Успешное сохранение

- **WHEN** backend подтвердил создание или правку песни
- **THEN** PWA получает актуальный снимок библиотеки и обновляет локальную копию

#### Scenario: Нет сети

- **WHEN** пользователь пытается сохранить песню без доступа к backend
- **THEN** PWA оставляет предыдущую подтверждённую версию и сообщает, что запись не выполнена

### Requirement: Одна форма и согласованные операции с файлами

PWA SHALL позволять выбрать вложения при создании песни и сохранять текстовые поля и изменения вложений по одной команде пользователя, используя отдельные серверные операции для текста, загрузки и удаления файлов. Загрузка SHALL отправлять multipart поле `file`, стабильный UUID в `X-Attachment-Id` и текущую ревизию песни в `If-Match`. После каждой подтверждённой операции с файлом PWA SHALL получать новую ревизию из снимка до следующей операции. PWA SHALL не передавать массив вложений в текстовой правке. При сбое после частично подтверждённых операций PWA SHALL показать фактический результат и обновить состояние с сервера.

#### Scenario: Новая песня с файлами

- **WHEN** пользователь выбирает изображения или MP3 в форме новой песни и нажимает сохранить
- **THEN** PWA создаёт песню, затем загружает выбранные файлы отдельными запросами и показывает подтверждённый результат

#### Scenario: Файл не загрузился после сохранения текста

- **WHEN** backend подтвердил текстовую правку, но загрузка нового файла завершилась ошибкой
- **THEN** PWA показывает, что текст сохранён, файл не добавлен, и отображает актуальную серверную песню

#### Scenario: Удаление вложения

- **WHEN** пользователь убирает существующее вложение и сохраняет форму
- **THEN** PWA отправляет отдельное удаление файла и после подтверждения обновляет снимок

### Requirement: Один MP3 на песню

PWA SHALL допускать не более одного MP3-плейбэка у песни и SHALL объяснять отклонение второго MP3, если существующий файл не отмечен для удаления в той же форме. Изображений может быть несколько. При замене прежний MP3 SHALL быть удалён на сервере до загрузки нового.

#### Scenario: Второй MP3

- **WHEN** пользователь выбирает MP3 для песни с уже существующим MP3, не отмеченным для удаления
- **THEN** PWA не отправляет второй файл и сообщает об ограничении

### Requirement: Согласованная локальная копия

PWA SHALL получать полный снимок библиотеки с `libraryId` и `libraryRevision` при запуске с сетью, после подтверждённых изменений и по ручной команде. PWA SHALL загружать недостающие файлы, проверять `byteSize` и SHA-256 `checksum` и публиковать в IndexedDB новую ревизию только после завершения снимка. Старые локальные записи SHALL быть отделены от подтверждённой серверной библиотеки. При ошибке получения снимка, файла или локальной записи SHALL оставаться предыдущая рабочая копия.

#### Scenario: Ручное обновление

- **WHEN** пользователь запускает обновление при доступном backend
- **THEN** PWA сохраняет актуальные песни и файлы и показывает время успешного обновления

#### Scenario: Ошибка обновления файла

- **WHEN** скачивание одного из файлов прерывается
- **THEN** PWA не объявляет новый снимок полностью доступным офлайн и сохраняет предыдущий

### Requirement: Офлайн-просмотр и конфликт правок

PWA SHALL открывать последнюю полностью сохранённую библиотеку для поиска, просмотра изображений и воспроизведения MP3 без сети. При `409 REVISION_CONFLICT` PWA SHALL получить актуальный снимок и сообщить о конфликте без автоматической перезаписи. При неизвестном результате записи PWA SHALL сверить состояние с сервером, прежде чем повторять запрос; для повтора создания и загрузки SHALL сохранять исходный ключ идемпотентности или UUID вложения.

#### Scenario: Запуск в авиарежиме

- **WHEN** пользователь открывает PWA после успешного обновления без сети
- **THEN** доступны песни, изображения и MP3 из сохранённого снимка

#### Scenario: Конкурентная правка

- **WHEN** backend отклоняет правку из-за устаревшей ревизии
- **THEN** PWA показывает конфликт, получает текущую песню и не отправляет правку повторно без действия пользователя

### Requirement: Проверка файлов не зависит от наличия Web Crypto

PWA SHALL проверять размер и SHA-256 каждого нового вложения при HTTP bootstrap и на постоянном HTTPS-origin. Отсутствие защищённого браузерного API SHALL не приводить к пропуску проверки целостности или ошибке обращения к отсутствующему digest.

#### Scenario: Первая синхронизация на HTTP

- **WHEN** браузер получает полный снимок на публичном HTTP-origin без нативного SHA-256 API
- **THEN** клиент вычисляет эквивалентный SHA-256, проверяет все файлы и публикует снимок только после успешной проверки

#### Scenario: Повреждённый файл на HTTP

- **WHEN** вычисленный SHA-256 не совпадает со снимком
- **THEN** клиент отклоняет новый снимок и сохраняет предыдущую завершённую копию

### Requirement: Новый origin получает копию с сервера

PWA SHALL получать данные от backend при первом открытии на новом постоянном origin. PWA SHALL не предполагать, что IndexedDB прежнего HTTP-origin доступен на HTTPS-домене, и SHALL не отправлять старую браузерную базу на сервер автоматически.

#### Scenario: Переход с IP на HTTPS-домен

- **WHEN** пользователь впервые открывает постоянный HTTPS-origin после работы по HTTP IP
- **THEN** клиент заново синхронизирует серверные песни и файлы, не удаляя и не дублируя server data

### Requirement: Офлайн-готовность подтверждается на защищённом origin

Production PWA SHALL поддерживать установленную оболочку и холодный офлайн-запуск на поддерживаемом устройстве после HTTPS и полной синхронизации. Работа открытой HTTP-страницы SHALL не считаться подтверждением установленного production offline mode.

#### Scenario: Приёмка после HTTPS

- **WHEN** пользователь установил PWA с HTTPS-origin, завершил синхронизацию и открыл её заново без сети
- **THEN** оболочка, поиск, изображения и MP3 доступны из подтверждённой локальной копии без записи изменений на сервер
