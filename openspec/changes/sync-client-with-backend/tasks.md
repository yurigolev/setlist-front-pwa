## 2. Запись через backend

- [x] 2.1 Перевести создание на `POST /v1/songs` со стабильным `Idempotency-Key`, текстовую правку и удаление на запросы с `If-Match`; не менять локальную копию до подтверждения.
- [x] 2.2 Перевести добавление и удаление вложений на отдельные API-операции; передавать UUID вложения и ревизию, получать новую ревизию после каждого шага, соблюдать лимиты типов/размеров и порядок замены MP3.
- [x] 2.3 Разрешить выбор файлов до создания песни, сохранить одну кнопку формы и показать частичный успех при сбое файла после подтверждённого текста; после каждого подтверждённого шага получать актуальный снимок.
- [x] 2.4 При отсутствии сервера сделать изменение библиотеки недоступным и сохранить поиск, просмотр и воспроизведение локальной копии.

## 3. Получение и хранение снимка

- [x] 3.1 Получать полный снимок при запуске с сетью, после успешной операции и по ручной команде; показывать время и ошибку последнего обновления.
- [x] 3.2 Разрешать `contentUrl` относительно backend, повторно использовать Blob с тем же attachment id/checksum, скачивать недостающие и проверять `byteSize`/SHA-256 `checksum`.
- [x] 3.3 Атомарно публиковать метаданные, файлы и `libraryRevision` в IndexedDB только после полной загрузки; при сбое сохранять предыдущий снимок, очищать временные файлы и не кэшировать API через service worker.
- [x] 3.4 Удалять из локальной копии песни и вложения, отсутствующие в новом снимке, не оставляя устаревшие файлы после успешной публикации.
