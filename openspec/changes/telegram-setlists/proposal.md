## Why

Сейчас единая библиотека и все изменения доступны без входа. Нужны подтверждённые пользователи Telegram, совместные сет-листы и серверные права доступа без потери существующих песен и файлов.

## What Changes

- Новый Telegram OIDC Authorization Code Flow с PKCE, серверными сессиями и выходом.
- **BREAKING**: анонимный доступ к приватным API библиотеки и файлам закрывается.
- Сет-листы с участниками owner/editor/viewer и ограниченными приглашениями.
- Изолированный локальный кэш пользователя и сет-листа, очистка при выходе и отзыве доступа.
- Аддитивный переход существующей библиотеки к явно назначенному владельцу, только локальная репетиция.
- Песня принадлежит ровно одному сет-листу; повторное использование создаёт независимую копию песни и файлов.

## Capabilities

### New Capabilities

- `telegram-authentication`: безопасный вход, сессия и выход.
- `collaborative-setlists`: участники, права и приглашения.
- `private-offline-cache`: изоляция приватных данных и защита от устаревших запросов.

### Modified Capabilities

Нет: основные specs пока пусты; предыдущие незавершённые changes сохраняются отдельно.

## Impact

Vue Router, Pinia, API client, IndexedDB, загрузка вложений и service worker. Совместимый контракт с setlist-back; production, коммиты и push не входят в эту работу.
