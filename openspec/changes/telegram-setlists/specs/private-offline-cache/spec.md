## Purpose

Сохранять доступные пользователю песни и вложения для работы без сети, предотвращая показ данных другого пользователя или сет-листа.

## ADDED Requirements

### Requirement: Изоляция кэша

Приложение SHALL разделять снимки, метаданные, файлы и состояние интерфейса по подтверждённому пользователю и выбранному сет-листу. Старый анонимный кэш MUST NOT автоматически становиться приватным кэшем пользователя.

#### Scenario: Совпадающий идентификатор

- **WHEN** два пользователя или сет-листа содержат одинаковый ID песни либо файла
- **THEN** каждый контекст читает только собственный сохранённый снимок и файл

### Requirement: Безопасная смена контекста

Приложение SHALL очищать прежние приватные данные из интерфейса при выходе, смене пользователя, смене сет-листа и подтверждённом отзыве доступа. Завершение старых запросов MUST NOT восстанавливать прежние данные или записывать их в новый контекст.

#### Scenario: Поздний ответ

- **WHEN** ответ снимка или файла приходит после выхода либо смены контекста
- **THEN** он не появляется в интерфейсе и не сохраняется как данные текущего контекста

### Requirement: Работа без сети

Приложение SHALL разрешать только чтение локальной копии выбранного сет-листа последнему подтверждённому пользователю; offline изменения MUST NOT выполняться; сетевой сбой MUST отличаться от явного 401/403. Выход SHALL удалять сохранённую идентичность, приватные кэши и object URLs. API и media ответы MUST NOT попадать в общий service worker cache. Навигация к /v1/auth SHALL проходить в backend даже под управлением установленного service worker, без SPA fallback.

#### Scenario: Перезапуск без сети

- **WHEN** приложение открывается без сети после успешной сессии без явного выхода
- **THEN** показывает только сохранённый контекст последнего пользователя с режимом без сети

#### Scenario: Другой пользователь после выхода

- **WHEN** после выхода приложение открывает другой пользователь
- **THEN** прежние песни и файлы не доступны через интерфейс и штатные repositories

#### Scenario: Вход установленной PWA

- **WHEN** установленная PWA с активным service worker открывает Telegram start или callback под своим origin
- **THEN** выполняется серверный auth endpoint, а cached index.html не подменяет ответ

### Requirement: Отказы текущего контекста

Подтверждённый отказ доступа SHALL очищать только текущий совпадающий user+setlist контекст. Поздний 403 предыдущего scope MUST NOT очищать выбранный новый сет-лист; CSRF_INVALID MUST NOT считаться отзывом доступа. 401 текущего поколения сессии SHALL сначала запускать восстановление через собственный refresh. Подтверждённое истечение refresh SHALL блокировать сетевые действия и сохранять локальную копию последнего пользователя для чтения; явный выход SHALL удалять приватные данные. См. change persistent-refresh-auth.

#### Scenario: Поздний отказ прежнего сет-листа

- **WHEN** пользователь переключился в доступный сет-лист, затем приходит 403 старого запроса
- **THEN** данные нового сет-листа остаются доступны и не очищаются

#### Scenario: Offline mutation

- **WHEN** приложение открыто без сети с сохранённым выбранным сет-листом
- **THEN** позволяет читать сохранённые песни и файлы, действия изменения и управления недоступны

#### Scenario: Понижение роли сохраняет чтение

- **WHEN** owner понижен до editor либо viewer и устаревший экран выполняет запрещённое управление
- **THEN** приложение обновляет роль, сохраняет доступ на чтение и не удаляет кэш доступного сет-листа

#### Scenario: Отзыв невыбранного сет-листа

- **WHEN** подтверждённый online список после reconnect больше не содержит ранее кэшированный невыбранный сет-лист
- **THEN** удаляется только кэш этого scope, остальные доступные сет-листы сохраняются
